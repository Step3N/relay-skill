# 安装与全局规则安全合并

仅在安装或更新时读取本说明。安装 Skill 不代表当前项目已启用记忆。

1. 阅读 README、SKILL、全局规则模板和准备执行的工具。根据用户给出的真实 GitHub URL 与版本获取源码，不编造地址，不执行未经审查的远程脚本，不采用下载后直接交给 shell 执行的安装方式。
2. 依据当前文档和实际客户端能力确认用户级 Skill 发现目录。现代 Codex 默认 `~/.agents/skills`；部分既有环境使用 `$CODEX_HOME/skills`，默认为 `~/.codex/skills`。新安装默认现代目录；只有一个已有安装且该目录可发现时才复用。新名 relay 或旧名 agent-continuity 在两处有多份副本时先报告歧义，不直接覆盖。已确认的其他目录使用 `--skills-dir`；目录存在本身不证明客户端能发现。
3. 全局规则位于 `$CODEX_HOME/AGENTS.md` 或 `~/.codex/AGENTS.md`。非空 `AGENTS.override.md` 会覆盖基础文件：不修改或删除它，也不声称基础触发块有效，先与用户解决。检查有关已有规则和禁用配置，不泄露秘密。自然语言规则冲突需要协调；安装器不能识别语义冲突或客户端指令大小限制，不自行改配置。
4. 只合并 `<!-- relay:start -->` 和 `<!-- relay:end -->` 之间的托管区，保留区外每个字节及换行习惯。没有标记时只追加一次；有且只有一对合法标记时只更新该区；不配对、嵌套、反向、行内或重复标记时不写入。唯一的旧版 agent-continuity:start/end 合法块会原位替换成 relay:start/end；新旧块同时存在则停止，不追加第二块。告知此区域由 Skill 管理，用户自定义放在标记外；修改前备份原文件。
5. 不覆盖未知来源的已有 Skill 或被本地修改的托管文件。安装凭据保存文件哈希，升级只替换未被修改的托管文件，保留用户新增文件；新版本与用户新增文件同名时停止。只有下述经过归属核验的旧名迁移会退役旧安装；其他安装不自行删除。链接或非普通目标停止写入。
6. 审查后可运行 Skill 中的 Python 3.10+ `scripts/install.py`。它默认官方用户目录，CODEX_HOME 决定全局规则位置，提供备份、安装锁和只读 `--check`。仅使用标准库，不联网、不运行下载程序、不改项目规则、不初始化 `.ai`。没有 Python 时可完成具有相同安全约束的文件操作；日常记忆维护不依赖 Python。
7. 检查资源、frontmatter、相对引用、单一托管块、安装哈希和区外规则保留，再重复安装确认无改动。隔离的可丢弃项目验证 init 保留已有记忆和 inspect 零写入；普通安装不用重复所有行为测试。不要只为测试安装而在当前项目创建记忆。
8. 文件完整不证明真实行为。新建 Codex 会话检查 Skill 发现和全局指令（全局规则在会话开始时加载）；Skill 可能自动刷新，必要时重启。分别验证项目任务自动维护和 resume 确认前零写入。无法执行的验证列为待验证。安装报告、项目总结和恢复汇报默认使用简体中文。

## 可选工具用法

从仓库根目录运行：

```sh
python3 skills/relay/scripts/install.py
python3 skills/relay/scripts/install.py --check
```

隔离测试时同时指定两处目录：

```sh
python3 skills/relay/scripts/install.py --skills-dir /absolute/test/user-skills --codex-home /absolute/test/codex-home
```

工具输出真实安装路径、变化、备份位置和发现状态。备份位于 `<codex-home>/.relay-backups/<id>/`，不在 Skill 发现目录内。无变化的重复安装及 `--check` 不创建备份或锁。各个文件使用原子替换，捕获错误时尽力回滚；进程被杀死或文件系统故障时不能保证两处写入是完整事务。中断后检查凭据、全局块和备份，再重试；不要盲目删除可能仍有安装器使用的锁。

## 从 Agent Continuity 迁移

首次安装 Relay 时，安装器在选定用户目录识别唯一的 `agent-continuity` 旧安装：

- 校验旧版 `.agent-continuity-install.json` 的名称与文件哈希。未知安装、托管文件有本地修改、新旧名称并存或规则标记异常时停止写入。
- 备份完整旧目录与原全局规则，保留用户新增文件及权限；新版本文件与用户新增文件同名时停止。
- 用 `relay` 目录与新凭据替代旧安装，原位迁移旧托管块中的名称、路径和标记，区外每个字节不变。成功后旧安装不再位于可发现的 `agent-continuity` 目录；完整副本在备份内。
- 迁移时同时使用新旧安装锁，避免和旧版安装器同时写入。全局写入失败时尽力恢复旧名目录，不覆盖并发改动。
- 现有项目 `.ai` 不改动。模板保留 `agent-continuity/v1` Schema 作为兼容格式，它不是调用名称；旧记忆不必重建。
- `--check` 只核验，发现待迁移旧安装时报告不一致，不执行迁移。安装后新会话使用 `$relay resume`；旧会话可能仍缓存旧规则，重新开会话使迁移生效。

进程在迁移途中被强制终止时，可能留下 `.relay-stage-*` 或 `.relay-previous-*` 暂存目录、锁、单处更新的规则。先核对备份、凭据、实际目录与规则，再恢复或重试；不能将安装成功推断为跨目标事务。

## 恢复与卸载

仅在用户要求卸载时，移除本 Skill 目录和唯一托管规则块；保留区外内容，不删除项目 `.ai` 记忆。恢复时先比较备份和当前文件，只恢复合适的托管内容；只有备份后未发生无关改动时才可整体还原。V1 刻意不提供盲目卸载或整体恢复命令。
