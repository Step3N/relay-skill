# 安装与管理说明

用户要求安装、更新或卸载 Relay 时，先读取本说明；安装或更新还需读取待安装源码中的 SKILL.md、全局规则模板和安装脚本。README 中的自然语言提示词是操作入口，本说明规定具体步骤与保护边界。安装 Skill 不代表当前项目已启用记忆。

## 安装与更新的共同规则

1. 阅读 README、SKILL、全局规则模板和准备执行的工具。根据用户给出的真实 GitHub URL 与版本获取源码，不编造地址，不执行未经审查的远程脚本，不采用下载后直接交给 shell 执行的安装方式。
2. 依据当前文档和实际客户端能力确认用户级 Skill 发现目录。现代 Codex 默认 `~/.agents/skills`；部分既有环境使用 `$CODEX_HOME/skills`，默认为 `~/.codex/skills`。新安装默认现代目录；只有一个已有安装且该目录可发现时才复用。Relay 在两处有多份副本时先报告歧义，不直接覆盖。已确认的其他目录使用 `--skills-dir`；目录存在本身不证明客户端能发现。
3. 全局规则位于 `$CODEX_HOME/AGENTS.md` 或 `~/.codex/AGENTS.md`。非空 `AGENTS.override.md` 会覆盖基础文件：不修改或删除它，也不声称基础触发块有效，先与用户解决。检查有关已有规则和禁用配置，不泄露秘密。自然语言规则冲突需要协调；安装器不能识别语义冲突或客户端指令大小限制，不自行改配置。
4. 只合并 `<!-- relay:start -->` 和 `<!-- relay:end -->` 之间的托管区，保留区外每个字节及换行习惯。没有标记时只追加一次；有且只有一对合法标记时只更新该区；不配对、嵌套、反向、行内或重复标记时不写入。告知此区域由 Skill 管理，用户自定义放在标记外；修改前备份原文件。
5. 不覆盖未知来源的已有 Skill 或被本地修改的托管文件。安装凭据保存文件哈希，升级只替换未被修改的托管文件，保留用户新增文件；新版本与用户新增文件同名时停止。其他 Skill 的安装不自行删除。链接或非普通目标停止写入。
6. 审查后可运行 Skill 中的 Python 3.10+ `scripts/install.py`。它默认官方用户目录，CODEX_HOME 决定全局规则位置，提供备份、安装锁和只读 `--check`。仅使用标准库，不联网、不运行下载程序、不改项目规则、不初始化 `.ai`。没有 Python 时可完成具有相同安全约束的文件操作；日常记忆维护不依赖 Python。
7. 检查资源、frontmatter、相对引用、单一托管块、安装哈希和区外规则保留，再重复安装确认无改动。隔离的可丢弃项目验证 init 保留已有记忆和 inspect 零写入；普通安装不用重复所有行为测试。不要只为测试安装而在当前项目创建记忆。
8. 文件完整不证明真实行为。新建 Codex 会话检查 Skill 发现和全局指令（全局规则在会话开始时加载）；Skill 可能自动刷新，必要时重启。分别验证项目任务自动维护和 resume 确认前零写入。无法执行的验证列为待验证。安装报告、项目总结和恢复汇报默认使用简体中文。

## 安装流程

1. 获取用户指定仓库的源码并记录提交；未指定版本时采用远端默认分支的最新提交。源码放在独立临时目录，不在 Skill 发现目录内直接克隆整个仓库，也不在已有安装中直接拉取代码。按共同规则审查源码、确认安装位置和全局规则位置。
2. 从该源码的仓库根目录执行下述安装命令。安装器只安装 `skills/relay` 的内容，自动备份并合并唯一托管块；不要另行手工追加同一份规则。
3. 按共同规则完成只读检查和重复安装核验，报告实际路径、Skill 版本、来源提交、备份位置及验证结果。文件检查通过与新会话实际发现、行为验证分别报告；无法完成的部分明确列为待验证，不只提供步骤就宣称完成。

## 更新流程

1. 先确认现有安装及全局规则位置，记录当前版本、安装凭据和托管块。多处安装、来源不明或标记异常时停止相关写入，先解决歧义。未安装时说明情况，不把首次安装报告成更新。
2. 重新获取仓库远端默认分支的最新源码；用户指定版本时使用该版本。记录新源码提交，不以缓存副本或现有安装目录作为“最新版本”的依据。审查新源码后，使用同一个安装器和已确认的两处目录进行升级，无需先删除旧安装。
3. 安装器依据 `.relay-install.json` 的文件哈希替换未被本地修改的托管文件，清理新版本不再包含的旧托管文件，保留用户新增文件；全局规则只更新原托管块，不重复追加。本地修改或新增文件与新版本冲突时停止相关写入并报告，不通过删目录重装绕过保护。项目 `.ai` 不参与更新。
4. 使用**新获取的源码**运行 `--check`，核对已安装文件、来源提交对应的内容、托管块和区外规则，再重复运行同一安装命令，确认没有新增写入。仅检查旧安装自身、只看版本号或看到命令退出成功，不能证明已升级；文档更新可能保持同一 Skill 版本号。
5. 报告更新前后版本、来源提交、实际变化、备份位置和验证结果。已经与最新源码一致时报告“已是最新，无需改动”。新会话发现与行为验证沿用共同规则，不修改或重建项目记忆。

## 安装与更新命令

从仓库根目录运行：

```sh
python3 skills/relay/scripts/install.py
python3 skills/relay/scripts/install.py --check
```

安装和更新使用相同命令。默认目录规则见上文；使用已确认的非默认目录时，对安装和检查都传入相同的 `--skills-dir` 和 `--codex-home`。隔离测试时必须同时指定两处测试目录：

```sh
python3 skills/relay/scripts/install.py --skills-dir /absolute/test/user-skills --codex-home /absolute/test/codex-home
python3 skills/relay/scripts/install.py --skills-dir /absolute/test/user-skills --codex-home /absolute/test/codex-home --check
```

工具输出真实安装路径、变化、备份位置和发现状态。备份位于 `<codex-home>/.relay-backups/<id>/`，不在 Skill 发现目录内。无变化的重复安装及 `--check` 不创建备份或锁。各个文件使用原子替换，捕获错误时尽力回滚；进程被杀死或文件系统故障时不能保证两处写入是完整事务。中断后检查凭据、全局块和备份，再重试；不要盲目删除可能仍有安装器使用的锁。

## 卸载流程

V1 没有卸载命令或 `--uninstall` 参数；由 Agent 按下述步骤完成文件操作。仅在用户要求卸载时执行，不运行安装器来尝试卸载。

1. **确认范围。** 只读检查当前客户端使用的 Skill 发现目录、实际 CODEX_HOME、全局 AGENTS.md 和 override。结合 `.relay-install.json`、SKILL.md 及托管块中的路径核验 Relay 的归属，列出将退役的安装目录、将移除的唯一 `relay:start/end` 块和备份位置。不能仅凭目录名删除；多份安装、归属不明、符号链接、非普通文件或不合法标记先报告并解决，不猜测范围。不能连带删除其他 Skill。
2. **保护用户内容。** 备份完整安装目录和原 AGENTS.md，保留文件权限，分别存为 `skill` 和 `AGENTS.md`，备份放在 `<codex-home>/.relay-backups/<id>/` 等不被客户端发现为 Skill 的位置。核对凭据与实际文件，说明本地修改和用户新增文件的备份去向，不直接销毁。保留所有项目记忆，包括 `.ai/PROJECT.md`、`.ai/HANDOFF.md` 及用户其他笔记；不扫描项目后批量删除 `.ai`，不修改项目规则、其他 Skill、客户端配置或 override。旧备份也不自动清理。
3. **移除托管配置。** 唯一且合法的 `<!-- relay:start -->` 至 `<!-- relay:end -->` 标记连同区内内容整体移除，只移除该字节区间，保留区外每个字节及换行习惯。全局 AGENTS.md 即使只剩空白也无需删除；缺少该块时不改文件。标记缺失一端、重复、嵌套、反向或非独占一行时不写入。区外或 override 中若有用户自定义 Relay 引用，报告具体位置并与用户协调，不把它当作托管内容直接删除。
4. **退役安装。** 写入前重新核对目录和规则快照，发生并发改动时停止并保留数据；不要盲目删除仍在使用的安装锁。将已确认的 Relay 安装目录移至同一备份目录下尚不存在的 `retired-skill` 子目录，使其离开所有已确认的 Skill 发现目录；移动前确认目标不存在且不经过符号链接。备份保留本地修改和用户新增文件，同时避免客户端继续发现 Relay。步骤失败时报告实际完成与未完成项，只回滚本次仍未被其他人改动的内容，不能用整个旧备份覆盖用户的新改动。
5. **验证结果。** 核对已确认的所有发现目录中 Relay 安装已不存在，全局托管块已移除，AGENTS 区外字节和其他配置不变，备份完整可读；已知项目记忆如有核验，只读比较，不能为验证创建或修改记忆。安装目录或全局块原本缺失时可清理已确认的剩余部分；两者均不存在时报告“已卸载”，不重复写入或创建备份。卸载后不使用安装器的 `--check` 作为成功条件，它检查的是安装存在且完整，卸载后应不通过。
6. **说明生效情况。** 在新 Codex 会话中确认 Relay 不再可用、托管规则不再加载；旧会话可能缓存已加载规则，必要时重启客户端。无法直接验证客户端状态时明确列为待验证。用中文报告退役路径、配置清理范围、保留的项目记忆、备份位置和验证结果；存在未处理的重复安装或自定义引用时，不宣称完整卸载。

## 从备份恢复

仅在用户要求恢复时，先比较备份和当前文件，只恢复合适的托管内容；只有备份后未发生无关改动时才可整体还原。V1 刻意不提供盲目卸载或整体恢复命令。
