# 安装与管理说明

用户要求安装、更新或卸载 Relay 时，先读取本说明。安装和更新还要审查准备使用的源码、SKILL.md、全局配置片段和安装脚本。

## 操作会改变什么

| 操作 | 改动范围 | 保留的内容 |
| --- | --- | --- |
| 安装 | 用户级 Relay Skill 目录，以及全局 AGENTS.md 中 Relay 的专属配置区域 | 其他配置、其他 Skill、所有项目记忆 |
| 更新 | 替换未被用户修改的 Relay 安装文件，更新原有专属配置区域 | 用户新增文件、区域外配置、所有项目记忆 |
| 卸载 | 让 Relay 安装离开客户端发现目录，移除它的专属配置区域 | 其他配置、其他 Skill、项目记忆，以及可恢复的备份 |

安装和更新不会在当前项目创建 `.ai`。只有开始实际项目工作时，才由 Skill 按需创建记录。

本说明负责决定什么时候执行、怎样处理冲突、怎样确认成功。`scripts/install.py` 负责安装和更新时的检查、备份和文件替换。它不联网，也不执行额外下载程序。

## 先确认位置和来源

### 获取源码

使用用户提供的真实仓库 URL，不猜测地址。未指定版本时，获取远端默认分支的最新提交；指定版本时采用该版本，并记录来源提交。

源码放在独立临时目录。不要把整个仓库克隆进 Skill 发现目录，也不要在已有安装中直接拉取代码。先审查脚本，再执行；不要采用下载后直接交给 shell 执行的方式。

### 确认安装目录

现代 Codex 默认从 `~/.agents/skills` 发现用户 Skill。有些既有环境使用 `$CODEX_HOME/skills`；未设置 CODEX_HOME 时，对应 `~/.codex/skills`。

新安装默认采用现代目录。如果只有一处已有 Relay 安装，并且当前客户端能发现它，就复用该目录。两处都有安装时，先报告冲突并确认实际使用位置，不覆盖、不删掉其中一份来绕过检查。

目录存在不代表客户端会读取它。其他已确认的位置可以通过 `--skills-dir` 指定。

### 确认全局配置

全局配置是 `$CODEX_HOME/AGENTS.md`；未设置 CODEX_HOME 时使用 `~/.codex/AGENTS.md`。

Relay 只管理以下标记之间的专属配置区域：

```text
<!-- relay:start -->
…Relay 配置…
<!-- relay:end -->
```

用户自定义规则应放在标记外。安装器保留区域外的原始内容和换行，不需要再手工追加一份片段。

非空的 `AGENTS.override.md` 会替代基础配置。安装器会停止写入；不要删除或改写 override 来强行安装。先与用户确认如何协调，不能宣称基础配置已经生效。

已有规则如果与 Relay 冲突，或客户端禁用了 Skill，也需要先协调。安装器检查文件结构，不能判断所有自然语言冲突或客户端读取限制；不要自行改客户端配置，不要在检查时输出秘密。

## 安装

1. 按上文获取并审查源码，确认两处目标位置。
2. 从源码仓库根目录运行安装命令。安装器只安装 `skills/relay` 内的内容，并安全合并全局配置。
3. 按“验证结果”检查安装。报告实际路径、源码版本、来源提交、备份位置和验证结果。

## 更新

1. 确认现有安装的归属、版本和配置位置。没有安装时说明情况，不把首次安装报告成更新。
2. 获取新的远端源码并审查。不要把缓存副本或已安装目录当作最新版本的依据。
3. 使用同一个安装器和已确认的位置更新，无需先删除旧安装。出现本地修改或文件冲突时，按下文停止并报告，不用删目录重装绕过保护。
4. 使用新源码验证。已经与最新源码一致时，报告“已是最新，无需改动”。

安装器的 `.relay-install.json` 记录安装文件及其内容哈希，也就是用于比较内容是否变化的摘要。它用来识别哪些文件由 Relay 安装、哪些内容后来被用户修改。

更新会移除新版本不再提供的旧安装文件，但会先备份。用户自行新增的文件保留；它们与新版本文件同名时停止写入。项目 `.ai` 不参与更新。

## 安装和更新命令

可选安装器要求 Python 3.10+，只使用标准库。从源码仓库根目录运行：

```sh
python3 skills/relay/scripts/install.py
python3 skills/relay/scripts/install.py --check
```

安装和更新使用相同命令。`--check` 只检查，不修复、不安装。它比较当前安装和执行命令的这份源码，因此更新后必须用新源码检查。

| 参数 | 作用 |
| --- | --- |
| `--skills-dir` | 指定已经确认的用户 Skill 发现目录 |
| `--codex-home` | 指定全局配置和备份所在目录；默认采用 CODEX_HOME 或 `~/.codex` |
| `--source` | 指定 Skill 源目录，默认是当前安装器所在的 `skills/relay` |
| `--check` | 只检查安装文件与全局配置是否和源码一致 |

安装、重复安装和检查必须使用相同的目标参数。隔离测试必须同时指定两处测试目录，避免接触真实用户配置：

```sh
python3 skills/relay/scripts/install.py --skills-dir /absolute/test/user-skills --codex-home /absolute/test/codex-home
python3 skills/relay/scripts/install.py --skills-dir /absolute/test/user-skills --codex-home /absolute/test/codex-home --check
```

没有 Python 时，可以使用同样保护用户文件的方式安装。下文的安全要求仍然适用，不能因为手工操作而省略。

## 哪些情况会停止写入

这些保护由安装器和文件测试实现，Agent 不需要在提示词中再复制一套底层算法。

| 情况 | 处理方式 |
| --- | --- |
| 已有 Skill 来源不明，或安装凭据无效 | 保留原安装，先核对归属 |
| Relay 安装文件被用户修改或缺失 | 停止更新，报告具体文件，不覆盖本地修改 |
| 用户新增文件与新版本同名 | 保留用户文件，停止更新并协调 |
| 配置标记缺失一端、重复、顺序错误或没有独占一行 | 不写全局配置，先处理异常标记 |
| 路径中有符号链接，或目标不是所需的文件、目录类型 | 停止对该路径写入，避免改到其他位置 |
| 非空 override，或两处重复安装 | 先确认配置或位置，不擅自清理 |
| 安装锁已存在 | 不执行另一轮写入，确认是否有安装器仍在运行 |
| 读取后文件又被其他人修改 | 停止本次覆盖，保留当前内容 |

重复安装不会产生重复配置。内容已相同时，不写文件，也不新增备份或锁。

真正修改前，安装器在 `<codex-home>/.relay-backups/<id>/` 备份原 AGENTS.md 和已有安装。备份不在 Skill 发现目录内。

每次文件替换都尽量避免写到一半，但 Skill 目录和全局配置是两处独立操作。出错时会尽力回滚；强制终止或文件系统故障时，可能只完成其中一处。先核对备份、安装凭据、实际文件、锁和 `.relay-stage-*` / `.relay-previous-*` 暂存目录，再恢复或重试。不要盲目删除锁或暂存内容，也不要用旧备份覆盖后来新增的用户改动。

## 验证安装和更新结果

分开报告以下检查，不能因为命令成功退出就宣称全部通过：

1. **文件检查。** 必要资源、Skill 元数据和引用有效；新源码的 `--check` 通过。全局配置只有一对合法 Relay 标记，区域外内容与操作前一致。安装器只检查必要文件及部分元数据，SKILL.md 开头和 openai.yaml 的 YAML 格式还要用可用解析器检查。
2. **重复操作。** 再运行同一安装命令，确认没有写入或重复配置。隔离项目中检查 init 保留已有内容、inspect 不写文件，不为安装验证在当前项目创建记录。
3. **客户端发现。** 新开 Codex 会话，确认 Relay 可用、全局配置已加载。没有刷新时再重启客户端。Skill 或文件存在不能代替这一步。
4. **实际行为。** 在隔离项目检查自动维护，以及 resume 确认前不修改文件。通常安装不用重复所有行为测试；无法执行的检查必须列为待验证。

报告默认用简体中文。写明安装或更新是否完成，以及哪些检查已通过、哪些还未执行。源码文档可能更新而版本号不变，因此还要核对来源提交和实际内容。

## 卸载

目前没有 `--uninstall` 参数。只在用户要求卸载时，由 Agent 按以下步骤操作；不要运行安装器来尝试卸载。

### 1. 确认清理范围

只查看当前客户端的发现目录、实际 CODEX_HOME、AGENTS.md 和 override。结合安装凭据、SKILL.md 和专属配置中的路径确认 Relay 的归属，列出将移出的安装目录、将移除的配置区域和备份位置。

不能仅凭目录名删除。多份安装、来源不明、文件类型异常或标记不合法时，先报告并解决。区外或 override 中的用户自定义 Relay 引用要另行协调，不能当作 Relay 专属配置直接删除。

### 2. 备份后移除配置

把完整安装目录和原 AGENTS.md 分别备份为 `skill` 和 `AGENTS.md`，保留权限。备份放在 `<codex-home>/.relay-backups/<id>/` 等客户端不会发现为 Skill 的位置。本地修改和用户新增文件也要保留，并说明备份去向。

只移除唯一、合法的 Relay 标记及其区内内容，保留区外每个字节和换行。没有该区域就不改文件；标记不合法就停止写入。即使移除后只剩空白，也无需删除整个 AGENTS.md。

### 3. 让安装离开发现目录

将已确认的安装目录移到同一备份目录下尚不存在的 `retired-skill`。移动前确认目标不存在，路径不经过符号链接。

每次写入或移动前重新核对相应文件。内容已变化就停止。步骤失败时说明完成了哪部分，只回滚本次操作且未被别人改动的内容，不整体覆盖用户的新配置。

不删除其他 Skill、其他配置、override、旧备份或项目规则。不删除、重建或修改任何项目记忆，包括 PROJECT、HANDOFF 和用户其他笔记。不要扫描项目后批量删除 `.ai`。

### 4. 验证卸载结果

- 已确认的发现目录中不再有 Relay 安装，专属配置区域已移除。
- 区域外配置、其他 Skill 和已核对的项目记忆不变，备份完整可读。
- 新会话中 Relay 不再可用，全局专属配置不再加载；必要时重启客户端。

不能用安装器的 `--check` 判断卸载成功：它要求安装存在且完整，卸载后应不通过。

安装或配置原本缺少一项时，可以清理已确认的剩余部分。两者均不存在时，报告“已卸载”，不重复写入或创建备份。还有重复安装或用户引用未处理时，不宣称完整卸载。

用中文报告处理范围、备份位置和验证结果。无法直接验证客户端状态时，明确列为待验证。

## 从备份恢复

仅在用户要求恢复时操作。先比较备份与当前文件，优先恢复需要的 Relay 内容。只有确认备份之后没有无关改动，才能整体还原。目前没有盲目卸载或整体恢复命令。
